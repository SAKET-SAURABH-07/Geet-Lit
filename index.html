geetlit

set up once — after that, add a number and it syncs to GitHub by itself.

Heads up: this only pushes a small .md file per entry — the problem number, date, and time — to your repo, so it shows up as a commit on your GitHub profile. It can't push your actual solution code, and it doesn't touch anything else in your account. Its only job is to save you the manual copy-paste of making a commit each time you solve one, without handing full GitHub account access to a third-party Chrome extension.

SET UP GITHUB IN 6 STEPS
  1. Open the token creation page Click github.com/settings/personal-access-tokens/new → (also linked next to the token field below). Sign in if asked.
  2. Name it and set an expiration Give it something recognizable like geetlit. Pick any expiration — 90 days is a safe default; you can generate a new one later.
  3. Limit repository access Under "Repository access," choose Only select repositories, then pick the one repo you want problems pushed to. Avoid "All repositories."
  4. Grant the Contents permission Scroll to "Permissions" → Repository permissions. Find Contents in the list and set it to Read and write. This is the only permission this tool needs — leave everything else on "No access." GitHub will auto-add "Metadata: Read-only" for you; that's expected.
  5. Generate and copy the token Click Generate token at the bottom. Copy the value shown — it starts with github_pat_ — you won't be able to see it again after leaving the page.
  6. Paste it in here and verify Open config above, fill in owner, repo, and this token, then click verify & save. A green "Connected to owner/repo" message means you're ready to push.
No storage is available at all. Entries and config will disappear on refresh. Private/incognito mode or blocked site data can cause this — try a normal browser window.
Entries and config are saved to this browser's local storage — they'll stay put on this device and browser, but won't follow you to another device or browser.
GITHUB CONFIG
Your exact GitHub username (or org name if the repo belongs to one) — not your display name, not your email. Check the address bar on your profile: github.com/yourusername → the part after github.com/ is the owner.
The exact repository name, case-sensitive, as it appears right after the owner in the repo's URL. github.com/owner/repo-name The repo has to already exist — this tool only writes files into one, it doesn't create repos.
github.com/owner/repo
Where inside the repo files get written — a subfolder, not the whole repo. leetcode/1234.md Leave blank to write straight to the repo root instead (1234.md). Nested paths like solutions/2026 work too — missing folders are created automatically on first push.
Owner and repo must match the URL exactly — github.com/OWNER/REPO — case-sensitive, no extra slashes. Use a fine-grained token scoped only to this repo with "Contents: Read and write". Don't have one? Create one on GitHub → then set "Repository access" to this repo and grant "Contents: Read and write" under permissions. The token is saved to this browser's storage for your account only, never shared, but treat it like a password.
